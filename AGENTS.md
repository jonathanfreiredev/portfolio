## Internationalization (next-intl)

Default locale is **English** (`en`). Spanish (`es`) is also supported. Every piece of user-facing copy in `app/` and `components/` flows through `next-intl` — see the rule below.

### The rule

**Write the canonical text in English in `locales/en.json`, then reference it via next-intl in the component.** Never hardcode user-facing strings inline in JSX, as a literal in `app/.../page.tsx`, or as a constant in a `components/*` file. This applies to:

- Page text (headings, paragraphs, buttons, labels, descriptions, error messages).
- UI chrome (nav links, theme toggle options, table-of-contents titles, aria-labels).
- `metadata.title` / `metadata.description` / `openGraph.*` returned from `generateMetadata` — resolve with `getTranslations`, do not return a literal.
- Placeholder text, tooltips, and anything else the user can read.

**Pick the right API for the environment. Both are part of the same rule; using the wrong one is the same bug as hardcoding.**

- **Client components** (`"use client"`, anything with hooks, event handlers, browser APIs) → `import { useTranslations } from "next-intl"`, then `const t = useTranslations("namespace")` and `t("key")`. The component must be a client component — `useTranslations` cannot be called from a server component.
- **Server components, `generateMetadata`, route handlers, server actions** → `import { getTranslations } from "next-intl/server"`, then `const t = await getTranslations({ locale, namespace: "namespace" })` and `t("key")`. Pass `locale` explicitly when calling outside a `[locale]` route segment.
- **Client-side programmatic navigation** (e.g. locale switcher) → import `Link`, `useRouter`, `usePathname`, `redirect` from `@/i18n/navigation`, never from `next/link` or `next/navigation`. Otherwise the locale prefix is lost.

Hardcoded strings in the codebase are a bug. If you find one, extract it.

### Adding a new string

1. Add the English copy to `locales/en.json` under the right namespace (`nav`, `blog`, `theme`, `notFound`, `tableOfContents`, `metadata`) or create a new namespace if it does not fit. Use ICU placeholders (`{folder}`) for any value that varies.
2. In the component, call `useTranslations("namespace")` (client) or `await getTranslations({ locale, namespace: "namespace" })` (server) and reference the key: `t("key")` or `t("key", { placeholder: "value" })` for ICU placeholders.
3. Do not touch `locales/es.json` — it is generated by **Crowdin** from `en.json` via the GitHub sync. The fallback in `i18n/request.ts` (`deepmerge` against `en.json`) covers any missing keys while Crowdin is in sync, so the build never breaks on missing translations.

### File map

- `locales/en.json` — source of truth for all UI text. Manually edited.
- `locales/es.json` — managed by Crowdin. **Never create, edit, or commit this file manually.**
- `i18n/routing.ts` — `defineRouting({ locales: ["en", "es"], defaultLocale: "en", localePrefix: "as-needed" })`.
- `i18n/request.ts` — `getRequestConfig` with a `deepmerge` fallback so non-default locales inherit any missing keys from `en.json`. This is the file wired into `createNextIntlPlugin` in `next.config.ts`.
- `i18n/navigation.ts` — `createNavigation(routing)` re-exports `Link`, `useRouter`, `usePathname`, `redirect`. Always import from here, never from `next/link` or `next/navigation`, so the locale prefix is applied automatically.
- `proxy.ts` — `createMiddleware(routing)` at the project root with the standard matcher `'/((?!api|_next|_vercel|.*\\..*).*)'`.
- `app/[locale]/` — all user-facing pages live under the locale segment. `app/robots.ts` and `app/sitemap.ts` stay at the root.
- `components/locale-switcher.tsx` — the EN/ES toggle in the navbar. Do not rebuild this; consume it.

### Locale detection

Handled by the next-intl middleware in this priority: explicit `/[locale]/` prefix → `NEXT_LOCALE` cookie → `accept-language` header → `defaultLocale` (`en`). The cookie is set when the user explicitly switches language (e.g. via the locale switcher in the navbar). `localePrefix: 'as-needed'` means the default locale has no URL prefix (`/blog` instead of `/en/blog`).
